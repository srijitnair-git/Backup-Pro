## Major finding: CI has never once passed
- Checked the Actions run history while watching the Release workflow: **every CI run on this repo has failed**, going back to the first commit that added the workflow. Nothing was ever actually built/verified automatically.
- Root cause: `flutter analyze` treats info-level lints (`avoid_print`, `deprecated_member_use`) as fatal by default in this Flutter version (`--fatal-infos` defaults to on) — and the codebase has had ~19 such pre-existing info-level notices since before this session (unrelated to today's work). On top of that, my own new test file briefly introduced a real warning (unused import/variable), which is a separate, correctly-fatal failure.
- Fixed both: removed the unused import and unused variable in `test/core_test.dart` (and made the second `withRetry` test actually assert on the retry count instead of leaving it unused), and added `--no-fatal-infos` to the CI analyze step so style-level notices stop blocking builds while real errors/warnings still do.
- Verified locally with the exact CI command (`flutter analyze --no-fatal-infos` → exit 0; `flutter test` → 6/6 pass).

## UI rework + VPN-off-network bug + Workmanager never initialized
- User reported: UI cluttered/overlapping, couldn't find the per-folder source/destination setting, and VPN doesn't try to connect off-network. Created `task-8-ui-rework-and-critical-fixes.md` before investigating.
- Launched the `Pixel_6_API_34` emulator and ran the real app via `adb`/screenshots instead of guessing from source — this caught two genuine overlap bugs a code read alone would have missed (or misjudged as "just tight spacing"): the folder card's `ListTile(isThreeLine: true)` clipping a 4th line of content (which is *why* the destination field looked missing — it wasn't missing, it was clipped), and the fixed `bottomNavigationBar` genuinely painting behind the last home-screen tile (confirmed by scrolling and seeing no change, proving content already fit and Scaffold wasn't reserving the space it appeared to need).
- Root-caused the VPN bug via a research subagent reading the `workmanager_android` plugin's Kotlin source: Workmanager's headless background isolate never sees channels registered only in `MainActivity.configureFlutterEngine` (only real pub-declared plugins via `GeneratedPluginRegistrant` make it into that engine), so the VPN launch call was throwing `MissingPluginException` silently inside every background sync attempt. Fixed by moving the launch call to `url_launcher` (a real plugin, works in both engines), verified via logcat that the background task now runs to completion instead of crashing.
- Also found, while testing "Sync Now" live: `BackgroundService().initialize()` — which calls `Workmanager().initialize()` — was never called anywhere in the app. Every sync attempt threw `PlatformException: You have not properly initialized the Flutter WorkManager Package.` Fixed by calling it in `main()`.
