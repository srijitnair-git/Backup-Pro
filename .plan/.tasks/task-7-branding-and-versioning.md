# Task 7: App Branding, Version Display & Versioned Releases

**Status**: COMPLETED

## Context
User asked to push to GitHub, but first: give the app a real logo/branding (it currently uses the default Flutter icon and `android:label="backuppro"`), and make sure every built/uploaded app artifact carries a version.

## Sub-tasks
- [x] Generated a launcher icon (cloud + upload-arrow mark, matching the `Icons.cloud_sync` iconography already used on the live-transfer dashboard) on the premium navy/accent-blue palette from `premium_theme.dart` — legacy PNG mipmaps (5 densities) + Android 12+ adaptive icon (`mipmap-anydpi-v26/ic_launcher.xml`, foreground PNGs + `@color/ic_launcher_background`).
- [x] Fixed `android:label` from `backuppro` to `Backup Pro`; matched iOS `CFBundleDisplayName`.
- [x] Native splash (`launch_background.xml`, both default and API21+ variants) now uses the brand navy instead of Flutter's default white.
- [x] App version + build number shown in the Settings screen footer via `package_info_plus`.
- [x] CI now resolves the version from `pubspec.yaml` and the GitHub run number, passes `--build-name`/`--build-number` to `flutter build appbundle`, and names the uploaded artifact with that version so every build is distinguishable.
- [x] Pushed to GitHub (`origin/main`, commits `68adbeb` and `79c55ed`).

## Known simplification
Icon generated by `tool/generate_icon.dart`, a one-off Flutter-test-based rasterizer using pure Canvas vector shapes (no font/glyph rendering — an earlier attempt using a Material Icon glyph via `TextPainter` hung indefinitely on font shaping in the headless test harness). No image-editing tool was available in this environment (no ImageMagick/Inkscape/rsvg-convert). Re-run `flutter test tool/generate_icon.dart` any time the mark needs to change.
